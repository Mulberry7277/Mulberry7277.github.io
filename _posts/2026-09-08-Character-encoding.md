如果计算机底层只有 0 和 1，那我们屏幕上五彩斑斓的文字、各种语言甚至 😂 表情包，究竟是怎么显示出来的？

这就不得不提到计算机历史上最伟大、也曾是最混乱的规则——**字符编码（Character Encoding）**。简而言之，这就是一本“密码本”，规定了哪个数字代表哪个字符。它的演进经历了三个标志性的阶段。

## 阶段一：ASCII码

计算机是美国人发明的，所以最早的密码本只考虑了英语。

计算机最小的存储单位是**字节（Byte）**，一个字节由 8 个二进制位（bit）组成，刚好可以组合出 256 种状态（从 `00000000` 到 `11111111`）。上世纪 60 年代，美国制定了 **ASCII 码**（美国信息交换标准代码）。

*   **规则：** 规定了 128 个字符的编码。比如空格是 `32`，大写字母 `A` 是 `65`（二进制 `01000001`）。
*   **特点：** 它只用了一个字节的后 7 位，最前面一位统一填 `0`。

对于纯英文环境，这本小册子完美运行了很久。

## 阶段二：诸侯割据（乱码时代的到来）

当计算机普及到欧洲和亚洲，问题出现了：128 个字符根本不够用。

*   **欧洲的扩展：** 法语有 `é`，德语有 `ä`。欧洲人决定把 ASCII 码闲置的最高位（第 8 位）利用起来，凑齐了 256 个字符。但各个国家的标准不统一，导致同一个数字在法国电脑上是 `é`，在俄罗斯电脑上可能变成了西里尔字母。
*   **亚洲的降维打击：** 中文汉字多达 10 万个，256 个位置连常用字都塞不下。于是中国制定了 **GB2312**（后来演进为 GBK 和 GB18030），规定用**两个字节**来表示一个汉字。

**“乱码”由此诞生：** 如果你用日本的 Shift-JIS 编码去打开一篇中国的 GBK 文档，计算机会用错误的密码本去查表，满屏就会出现类似“锘匡綅”的火星文。

## 阶段三：大一统帝国 Unicode（万国码）

为了消灭乱码，国际组织决定秦始皇式的“书同文”：建立一个足以囊括地球上所有人类语言（甚至包括甲骨文、盲文以及 Emoji 表情包）的超级密码本——**Unicode**。

*   **容量惊人：** Unicode 目前的空间可以容纳约 111 万个字符。
*   **众生平等：** 每个符号都有一个独一无二的编号（码点）。比如，英文字母 `A` 是 `U+0041`，汉字 `严` 是 `U+4E25`，而笑哭表情 😂 是 `U+1F602`。

### Unicode 遭遇的现实阻击

Unicode 只是规定了“编号”，却没规定**“在硬盘上怎么存”**。
如果统一用 3 到 4 个字节来存所有字符，那原本只占 1 个字节的英文字母 `A`，前面就必须强行塞入一堆 `0`。这在早期寸土寸金的硬盘和慢如蜗牛的网速面前，意味着存储空间和流量将被浪费 3 倍以上。欧美国家根本无法接受。

## 阶段四：伟大的工程师妥协 —— UTF-8

为了拯救 Unicode，**UTF-8** 诞生了。它最大的天才是：**变长编码**。它就像一辆有弹性的公交车，胖子多占几个座，瘦子少占座，绝不浪费空间。

UTF-8 使用 1 到 4 个字节来表示一个符号，规则极其优雅：

| Unicode 符号范围 (十六进制) | UTF-8 编码方式 (二进制格式)           | 说明                                            |
| :-------------------------- | :------------------------------------ | :---------------------------------------------- |
| `0000 0000` - `0000 007F`   | `0xxxxxxx`                            | **1字节**：完全兼容 ASCII。英文完全不浪费空间。 |
| `0000 0080` - `0000 07FF`   | `110xxxxx 10xxxxxx`                   | **2字节**：拉丁文、希腊字母等。                 |
| `0000 0800` - `0000 FFFF`   | `1110xxxx 10xxxxxx 10xxxxxx`          | **3字节**：基本涵盖所有常用的中文汉字。         |
| `0001 0000` - `0010 FFFF`   | `11110xxx 10xxxxxx 10xxxxxx 10xxxxxx` | **4字节**：极其生僻的汉字、Emoji 表情包等。     |

*解读技巧：如果一个字节的第一位是 `0`，说明这是单字节字符；如果第一位是 `1`，那么开头有几个连续的 `1`，就代表这个字符由几个字节组成。*

## 阶段五：历史遗留问题与现代进化（BOM 与记事本）

在老旧的 Windows 时代（如 Win7），如果你用记事本保存文件，会看到 `ANSI`、`Unicode` (实际上指 UTF-16)、`UTF-8` 等选项。

当年为了区分文件是用“大端（Big-endian）”还是“小端（Little-endian）”顺序存储，Windows 会在文件头部塞入两个看不见的字符（叫作 **BOM** 签名，如 `FE FF`）。Windows 甚至自作主张给 UTF-8 也加了 BOM（即 `EF BB BF`）。

**时代的眼泪：**
给 UTF-8 加 BOM 是一个极其糟糕的决定，它曾导致无数程序员的代码报错（比如 PHP 输出异常）。如今，历史已经翻篇：
1. **UTF-8 彻底统治世界：** 互联网上 98% 的网页都在使用 UTF-8。
2. **微软的妥协：** 从 Windows 10 开始，自带的记事本默认编码终于改成了 **“不带 BOM 的 UTF-8”**，曾经的 `ANSI`（根据地区自动调用 GBK 等）被彻底降级。

当年那个因“吃鸡蛋先敲大头还是小头”引发的 Endian 战争，终于在 UTF-8 的光辉下成为了历史的尘埃。
